# v0.7.1 release scope

Status: release candidate prepared for manual publication. Full Live success is not claimed. This document does not change provider defaults, publish credentials, or Git tags.

## Release intent

v0.7.1 is limited to safety, diagnostics, and clean-finalization/termination compatibility. It does not claim full Live character-generation success.

## Included scope

- Provider-neutral exact `FINALIZE` termination: surrounding whitespace is accepted; prose, wrappers, JSON, Markdown, and alternate signals remain rejected.
- Fail-closed action-round exhaustion: reaching `max_tool_rounds` without exact termination does not invoke finalization.
- Clean finalization context: provider-facing finalization receives the original user context plus deterministic Evidence Bundle data, without retrieval assistant/tool history.
- Observation-grounded Evidence Bundle construction with source ID/type validation, restricted-lore gating, bounded search selection, provenance, and fail-closed missing/unknown source handling.
- One clean source set shared by finalization payload, grounding validation, contract recovery, `CharacterGenerationResult.sources`, and success audit source IDs.
- Safe diagnostics with fixed failure phases/reasons and sanitized provider metadata; no raw provider body, headers, prompt, model output, secret, or unprocessed recovery exception text retention.
- CharacterDraft contract recovery writes only fixed, exception-class-based diagnostics to `CharacterDraftRecoveryAudit.error_message`; the original exception still propagates unchanged for fail-closed handling.
- Targeted termination, context, adapter/provider serialization/error, and audit-artifact checks.
- The Phase 4 offline audit artifacts, including the real deterministic/model-loop reports and Flash/Pro finalization probes.

## Explicitly excluded

- Any provider profile, provider, model default, OpenCode configuration, timeout, retry, or backoff change.
- Switching deterministic retrieval to the default strategy.
- Retrieval planner, Reference Selector, combat-role, or model-loop behavior redesign.
- Relaxing grounding, Canon Checker, Canon source/type checks, Repair, CharacterDraft validation, or restricted-lore policy.
- Declaring synthetic probe success as full Live generation success.
- A release tag, package-version edit, push, or commit.

## Evidence and current boundary

- The representative deterministic Live report reached one real finalization invocation with one retrieval source observation and timed out after bounded attempts.
- The representative model-loop Live report had retrieval action calls and tool events but failed before finalization with malformed termination; finalization invocation count was zero.
- The Pro clean finalization baseline remained 3/3 timeout in the finalization contract probe; the Pro fixed matrix recorded 26/30 success, but its synthetic payload variants are not a full Live-generation result.
- The Flash U0–U4 protocol baseline recorded 15/15 success under the same clean system+user, tools=0, no-history, `json_object` shape.
- Flash lexical/field isolation remained noisy (14/30 success overall); the semantic, field-location, and payload-size causes are not separated.

## Acceptance gates before release

1. Focused tests pass for exact termination acceptance/rejection, tool-call precedence, round-exhaustion fail-closed behavior, and separation of action-termination versus finalization-context failures.
2. Focused context tests pass for observation-derived Evidence Bundle facts, source ID/type fail-closed behavior, restricted-lore enforcement, bounded pruning, shared final source sets, and clean recovery context reuse.
3. Adapter/provider contract checks confirm two clean provider messages (`system` + `user`), zero tools, no history/tool calls, and negotiated `json_object` for CharacterDraft finalization.
4. Safe-diagnostics checks confirm fixed metadata only and reject raw body, headers, full prompt, model output, API key, and unprocessed exception text at audit boundaries, including CharacterDraft recovery audit failure paths.
5. Existing offline audit artifacts remain parseable and content-free. A real Live success rate is not an acceptance criterion for this scope, but any newly observed protocol regression is a release blocker.

## Known risks

- Pro full-finalization requests still time out in the representative finalization probe.
- Flash minimal protocol payloads succeeded, but lexical isolation shows provider noise and cannot explain the Pro/Flash or field/semantic difference causally.
- Three-repeat probes and one representative Live run are diagnostic evidence, not a stability guarantee across providers, models, or payloads.
- Full Live success is not claimed: the Pro finalization timeout remains a provider/model risk outside this scope.

## Rollback

Rollback for this scope is limited to the listed source/test/documentation changes; revert those files together while preserving unrelated worktree changes and prior audit artifacts. No provider configuration, timeout, version metadata, tag, commit, or remote state is changed.
